= Introduction to Ansible Automation Orchestrator

== Introduction

=== What Is Automation Orchestrator?

Ansible Automation Orchestrator is an add-on to Red Hat Ansible
Automation Platform: a composable canvas for designing, deploying and
governing complex IT operations workflows.

A workflow is a sequence of connected *steps*. A trigger starts it,
steps do the work, and logic steps decide which step comes next. The
steps themselves are the pieces you already own. Every certified job
template, role and collection becomes a reusable workflow step
immediately, without modification. Alongside them sit approval gates,
REST API calls, and task agent steps backed by an AI model.

It does not replace the playbooks, job templates and automation you
already have. It connects them, and it does it inside Ansible
Automation Platform, under the same governance and the same control
plane.

=== Why Should You Care?

Ansible Automation Platform already orchestrates. Workflow templates
chain job templates together, branch on success and failure, and start
from a schedule or a webhook. That is a lot of orchestration, and none
of it goes away.

What has grown is everything around it. An alert arrives as free text
that someone has to read before anyone knows which automation applies.
A change to production needs a person to sign off. A monitoring tool,
a ticketing system and a chat channel all need to take part, and none
of them is an Ansible target. Those pieces tend to end up outside the
platform, in glue scripts, one-off playbooks, a wiki page, or
somebody's head.

Automation Orchestrator gives them somewhere to live: on the same
canvas as the automation they govern, as one artifact you design
visually, control with RBAC and approval gates, export as YAML, and
commit to Git.

=== What Changes on the Canvas

*Triggers all live in one place.* Manual, scheduled, webhook and
Event-Driven Ansible triggers can all start the *same* workflow. A
monitoring alert and a nightly scan that find the same problem feed one
remediation workflow instead of two. And the finished workflow exports
as a single YAML file. Triggers, logic, approvals and job templates
all travel as one artifact, so it can go into Git and be handed to
another team.

*Logic steps route on real values, not just success or failure.* The
switch step reads a value from earlier in the workflow and takes the
first path that matches. Disk at 60% does nothing, at 75% cleans up, at
85% expands, at 95% gets a human involved. One metric, four paths.

*AI provides recommendations, AAP is still your trusted execution
layer.* A task agent step can read an alert, a log dump or the text of
an incident ticket, summarize it, classify it and recommend what to
run. Then an approval step can put a human in front of that
recommendation before Ansible Automation Platform executes the job
template you already trust. The reasoning is non-deterministic; the
change to your infrastructure is not.

=== What You Will Build

Across six modules you build up from a single connection to three
complete, running workflows:

* Your own *integrations and credentials*, connecting Orchestrator to
  Ansible Automation Platform and to an AI model
* A *Hello World workflow* on an empty canvas: a trigger, a task agent,
  and an AAP job template
* A *disk utilization workflow* that branches on how full a filesystem
  is and hands the fix to AAP
* A *ticket enrichment workflow* where a task agent reads a live
  incident ticket and routes it to remediation, to an approval gate, or
  back to a human
* A *CVE remediation workflow* that patches development hosts
  automatically and holds production for approval

Every one of them ends in a live run you can watch step by step.

== Who Will Benefit

This is a hands-on introduction to Automation Orchestrator. It assumes
no prior experience with it, and you will finish every module without
writing a playbook.

You will get the most out of it if you are:

* An automation engineer or platform team member who wants to see what
  Orchestrator adds to the Ansible Automation Platform you already run
* Dealing with alerts, tickets or logs that someone has to read and
  interpret before anyone knows which automation to run
* Curious what AI-assisted triage looks like when a human approval
  gate still sits in front of every change
* Evaluating Automation Orchestrator and would rather build something
  real on the canvas than watch a demo

If you know roughly what an Ansible playbook and an AAP job template
are, you have everything you need to complete every module.
